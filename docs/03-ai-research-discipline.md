# 03 · AI 研究员纪律：把"不许编"变成可执行的规则

这个系统的研究半场是一个 AI Agent：它上网查 FedWatch 概率、市场行情、投行观点、
其他央行动向，然后把结果填进卡片。

**它最大的风险不是能力不足，而是自信地编造。**
金融信息一旦编错，读者会据此做真实决策——所以这里的规则全是硬约束，
不靠"提示模型要准确"这种安慰性措辞。

## 一、五条硬规则

### 规则 1：实际值 ≠ 预期值（不许拿 consensus 冒充 actual）

```
✅ 非农实际 +9.5万 ｜ 预期 +8.3万 ｜ 前值 +5.7万
❌ 非农 +8.3万                      ← 拿预期冒充实际，最严重的一类错误
```

发布延迟时，宁可标注"实际值未获取"，也不许用预期值填空。

### 规则 2：拿不到就写「未获取」，不许留空、不许估

```
✅ 10年期美债收益率：未获取（源站超时）
❌ 10年期美债收益率：约 4.99%
❌ 10年期美债收益率：4.99%左右
```

### 规则 3：禁止模糊词与近似号

| 禁用 | 原因 | 替代 |
|---|---|---|
| `≈`、`约`、`左右` | 读者无法判断误差范围 | 给具体数值，或写"未获取" |
| "走弱""偏强""承压"（单独出现） | 无基准、无法复核 | `-0.8%`、`跌破 100`、`较前值 -0.3pp` |
| "市场普遍认为" | 无法溯源 | 点名来源：`彭博调查 +8.3万` |

### 规则 4：每个数值带来源

BLS / BEA / 美联储 / CME FedWatch / 路透 / 彭博——**写清是哪个口径**。
预期值要给调查来源（彭博调查 ≠ 道琼斯调查，数字可能差一截）。

### 规则 5：给框架，不给结论（哨兵不做投行）

三种情景（超预期 / 符合 / 低于）分别意味着什么，交给读者判断；
**不写"建议买入/卖出"，不做仓位建议**。这条写进了产品说明书，
也是模板注释里的固定要求。

## 二、规则怎么落地（不是写在提示词里就完了）

| 机制 | 作用 |
|---|---|
| 模板占位符固化 | 卡片里"实际 / 预期 / 前值"是三个独立占位符，想混也混不进去 |
| 未获取分叉 | 数据没拿到时，**不生成全量快报**，单独推一张「数据未获取」说明卡——宁可少发，不许编 |
| 退出码判据 | 分发脚本返回 `ok=false` 即视为失败，不允许"看起来发出去了"就算完成 |
| 定期人审 | 样张在生产环境里被真实订阅者阅读，错误会被指出来 |

**关键点：把纪律做成结构，而不是做成提醒。** 提示词里的"请注意准确"
在长会话里会衰减；把"实际值和预期值分成两个字段"这种结构约束不会。

## 三、为什么这半场值得用 AI

传统做法是写爬虫抓数据。现实是：

- FedWatch 概率藏在交互式页面里，正规 API 不开放；
- 投行观点散落在各家研报摘要与新闻里，没有结构化源；
- 事件日程的变动（改期、tentative）需要阅读理解，不是字段读取。

AI Agent 在这类"半结构化信息 + 需要判断"的任务上是**目前唯一可行**的方案。
代价是必须接受它的不可靠性，并用上面 5 条规则把不可靠性**关进笼子**。

## 四、这套纪律的可迁移性

任何"AI 生成的内容会流向真实决策"的场景都适用同一模式：

1. **区分事实字段与推断字段**（实际值 vs 观点）；
2. **给未知一个显式表示**（"未获取"是一个合法值，不是失败）；
3. **把来源当必填项**；
4. **禁止不可复核的修饰语**；
5. **输出侧加确定性校验**（结构、退出码、样本对账）。

这五条与另一个仓库
[blackbox-indicator-reverse](https://github.com/Roy9608/blackbox-indicator-reverse)
里的"逐点对账"是同一族纪律：**在 AI 参与的生产链路里，
可信度来自可复核的结构，不来自模型的自信。**
